0. 两个 Pass 各自做什么

SP passvllm_ascend/compilation/passes/sequence_parallelism.py —— 把 TP 的 all_reduce + AddRMSNorm 换成 reduce_scatter + AddRMSNorm + all_gather， 让 norm 在 [T/2, 2048] 分片上计算（也匹配 MoE 输出的 maybe_all_reduce 变体）。

MoE passvllm_ascend/compilation/passes/sequence_parallelism_moe.py —— 只在 SP+EP MoE 模式下生效，两个 pattern：

  • Pattern ① AllGatherChunkNoOp：all_gather + sequence_parallel_chunk → identity。 MoE 本来就吃 token 分片，先 gather 再切回原分片是纯往返，直接折叠。
  • Pattern ② MiddleLayerAllgatherAddRMSNorm：all_gather + slice + AddRMSNorm → AddRMSNorm + all_gather。 把 MoE 输出后的 all_gather 挪到下一层 RMSNorm 之后，norm 改在分片上算。

生效条件：compile_range.start ≥ sp_min_token_num（MoE 模型默认 1，dense 默认 1000，benchmark 中常设 1024）。

1. SP + EP MoE 模式（DP=2, TP=2, EP=4）

fused MoE 输入/输出都是 token 分片 [T/2, 2048]，内部 EP all2all（128 experts → 32/rank），输出后不做 TP all-reduce。 日志实测：SP pass 替换 48 处（每层 1 处，o_proj 后），MoE pass 替换 96 处（每层 2 处：pattern ① + ②）。

变化要点：
  • 每层通信从 2 次 all_gather + 1 次 reduce_scatter + 1 次 chunk 往返 降到 1 次 all_gather + 1 次 reduce_scatter。
  • MoE 前的 all_gather + sequence_parallel_chunk 是恒等往返，被 pattern ① 折叠；gate GEMM 改在 [T/2, 2048] 分片上算。
  • MoE 输出的 all_gather 被 pattern ② 挪到下一层 norm 之后 —— 它仍然存在，因为 attention 需要完整序列（qkv GEMM 输入必须是 [T, 2048]），但 norm 本身在分片上完成。

2. TP 模式（DP=1, TP=2, EP=2，MoE 非 SP）

fused MoE 输入/输出都是完整 tensor [T, 2048]，内部 EP all2all（64 experts/rank）+ 最终 TP all_reduce。 只有 SP pass 生效：每层替换 2 处（o_proj 后、MoE 输出后），48 层共 96 处。MoE pass 不生效。

  • MoE 入口前必须 all_gather 回 [T, 2048]，因为该模式下 fused MoE 要求完整 tensor（内部自己做 all2all + 最终 all_reduce）。

3. TP 模式，EP off（TP=2）

外部数据流与情况 2 的 After 完全相同（SP pass ×96）；区别只在 fused MoE 内部：无 all2all，expert 按 TP 切分（moe_intermediate 768 → 384/rank）， 外部的 all_gather / reduce_scatter 实际上充当了 expert 的 dispatch / combine。

一句话理解：SP+EP MoE 模式下 MoE 输出天然就是分片，任何「gather 完整 tensor」的动作都是浪费， MoE pass 的全部工作就是把这两处浪费消掉；而 TP 模式下 MoE 要完整 tensor，SP pass 只能在 norm 前后做 reduce_scatter / all_gather 配对，通信次数降不下来。上游 vLLM 的做法是 all_gather 后 slice 成分片输入，效果类似但多一次 gather。
