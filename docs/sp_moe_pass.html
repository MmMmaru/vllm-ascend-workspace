① SP + EP MoE 模式（DP=2, TP=2, EP=4）

Before 为 pass 前原始 FX 图；After = SP pass ×48 + MoE pass ×96 之后。fused MoE 分片进、分片出。

Before（原始图）

After（SP ×48 + MoE ×96）

  • 每层通信：1 all_reduce + 1 all_gather → 1 reduce_scatter + 1 all_gather；两处 norm 从 [T, 2048] 降到 [T/2, 2048]，sequence_parallel_chunk 消失。
  • 中间过程：SP pass 先在 MoE 前制造出 all_gather + sp_chunk 恒等往返，MoE pass pattern ① 将其折叠；pattern ② 把 MoE 输出后的 all_gather 挪到下一层 norm 之后（gather 仍保留，因为 attention 需要完整序列）。

② TP 模式（DP=1, TP=2, EP=2，MoE 非 SP）

只有 SP pass 生效：每层替换 2 处（o_proj 后、MoE 输出后），48 层共 96 处。fused MoE 完整 tensor 进、完整 tensor 出。

Before（原始图）

After（SP ×96）

  • 两处 all_reduce（o_proj 后、MoE 后的 maybe_all_reduce）都被拆成 reduce_scatter + all_gather，中间 norm 在 [T/2, 2048] 分片上算。
  • MoE 入口前必须 all_gather 回 [T, 2048]：该模式 fused MoE 要求完整 tensor。通信量不减（all_reduce ≈ RS+AG），收益在 norm 计算减半与通信/计算重叠。

③ TP 模式，EP off（TP=2）

外部数据流与情况 ② After 完全相同（SP pass ×96）；区别只在 fused MoE 内部。

After（SP ×96，同情况 ②）

  • MoE 内部无 all2all：expert 权重按 TP 切分（moe_intermediate 768 → 384/rank），输入输出均为 [T, 2048] 完整 tensor。
  • MoE 前的 all_gather 实际充当 expert dispatch，MoE 后的 reduce_scatter + all_gather 充当 combine。

一句话理解：SP+EP MoE 模式下 MoE 输出天然就是分片，任何「gather 完整 tensor」的动作都是浪费， MoE pass 的全部工作就是把这两处浪费消掉；而 TP 模式下 MoE 要完整 tensor，SP pass 只能在 norm 前后做 reduce_scatter / all_gather 配对，通信次数降不下来。上游 vLLM 的做法是 all_gather 后 slice 成分片输入，效果类似但多一次 gather。
