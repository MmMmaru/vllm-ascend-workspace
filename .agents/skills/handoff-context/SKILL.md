# Handoff Context（项目上下文交接）

## 触发场景

- **了解项目 / 熟悉项目 / 继续之前的工作**：直接读取 CONTEXT.md，恢复上下文后继续任务，不要重复通读源码。
- **理解项目 / 分析项目 / 更新上下文**：阅读源码，构建或增量更新 CONTEXT.md。

## 核心文件

- **CONTEXT.md**：项目根目录下的上下文交接文档（唯一维护对象）。
- **CONTEXT_template.md**：本 skill 目录下的结构模板。新建 CONTEXT.md 时严格遵循其章节结构；不要修改模板本身。

## 工作流程

### 了解项目（读取）

1. 读取项目根目录的 CONTEXT.md。
2. 若不存在，告知用户并询问是否需要执行"理解项目"流程生成。
3. 读取后简要复述当前环境、架构和主要修改文件，确认与用户的任务一致。

### 理解项目（构建/更新）

1. 阅读源码：优先看入口、核心模块和当前任务相关文件，避免无目的全量通读。
2. 已有 CONTEXT.md 时增量更新：保留仍准确的内容，修正过时部分，补充新理解的模块；没有则按 CONTEXT_template.md 新建。
3. 文件索引按模板分两组：
   - **当前主要修改文件**：本轮任务正在改动的文件，一句话说明功能与改动点。
   - **相关文件**：调用链上下游文件，一句话说明功能，作为下一个 agent 的索引。
4. 所有文件引用使用可点击的 markdown 链接 `[name](path)`。

## 硬约束

- CONTEXT.md 总行数不超过 800 行；超出时优先压缩"源码理解"中最陈旧的细节，保留文件索引和架构图。
- 只记录从源码确认的事实；推测性内容标注"待验证"。
- 环境配置章节记录可复现的运行方式（容器、PYTHONPATH、权重路径等），不写密钥和临时状态。
- 单次更新聚焦当前任务相关的模块，不重写与任务无关的章节。
